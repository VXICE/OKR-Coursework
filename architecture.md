# Архитектура курсового проекта: Система отслеживания целей OKR

## 1. Общая структура проекта

Репозиторий организован в виде монорепозитория из двух независимых TypeScript-проектов (`type: "module"`):

1. **`ui-library` (`@my-app/ui-library`)** — библиотека переиспользуемых UI-компонентов и чистых функций предметной области (расчёт прогресса OKR, вклада ключевых результатов и валидация данных). Не зависит от конкретного приложения, собирается в ES-модуль (`dist/index.js`, `dist/index.d.ts`, `dist/index.css`) и не использует сторонних UI-библиотек.
2. **`frontend`** — основное одностраничное веб-приложение (SPA) на React + TypeScript + Vite с клиентской маршрутизацией, хранением состояния в `localStorage` и интерактивным управлением целями и ключевыми результатами.

## 3. Список разрабатываемых компонентов

### В проекте `ui-library`
1. **`OkrGoalCard`** — карточка цели OKR: отображает название цели, дедлайн, статус (`Не начато`, `В работе`, `Срочное`, `Выполнено`), кнопку переключения статуса «Срочное», сегментированный прогресс-бар (10 сегментов по 10% + точный процент) и слот `children`.
2. **`KeyResultList`** — список ключевых результатов (KR): отображает название, прогресс `выполнено current из target`, вклад каждого KR в общий прогресс цели, мини-шкалу прогресса и элементы управления (`range` и `number`) с колбэком `onProgressChange`; автоматически перемещает выполненные KR (100%) в конец списка.
3. **`Button`** — базовая кнопка с вариантами оформления (`primary`, `secondary`), размерами (`small`, `medium`, `large`) и состоянием `disabled`.
4. **`Card`** — универсальная карточка-контейнер с опциональным заголовком `title` для форм и информационных блоков.

### В проекте `frontend`
1. **`Layout`** — общая оболочка всех страниц: шапка приложения, индикатор общего прогресса по всем целям, навигационная панель со счётчиками активных и выполненных целей и точка рендера дочерних маршрутов (`<Outlet />`).
2. **`GoalsPage`** — страница отображения активных (незавершённых) целей с быстрым редактированием прогресса и переходом на детальную страницу каждой цели.
3. **`CreateGoalPage`** — страница с формой создания новой цели (валидация названия и срока `ДД.ММ.ГГГГ`) и автоматическим переходом на страницу созданной цели.
4. **`GoalDetailsPage`** — детальная страница конкретной цели по её `id`: карточка цели, список её ключевых результатов и форма привязки нового KR к данной цели.
5. **`CompletedGoalsPage`** — страница выполненных целей, достигших 100% прогресса.
6. **`NotFoundPage`** — страница ошибки 404 для несуществующих URL с кнопкой возврата на главную.

## 4. Структура роутинга

Маршрутизация реализована в [`frontend/src/App.tsx`](frontend/src/App.tsx) с помощью `react-router-dom` (`BrowserRouter` в `main.tsx`, `Routes` и вложенные `Route`).

| Маршрут | Страница / Компонент | Вложенность | Параметры | Назначение |
| --- | --- | --- | --- | --- |
| `/` (оболочка) | `Layout` | Корневой layout-маршрут | — | Шапка, общий прогресс-бар, панель навигации (`NavLink`) и `<Outlet />` |
| `/` (`index`) | `GoalsPage` | Вложен в `Layout` | — | Список активных целей (`прогресс < 100%`) |
| `/create` | `CreateGoalPage` | Вложен в `Layout` | — | Форма создания новой цели OKR |
| `/goals/:id` | `GoalDetailsPage` | Вложен в `Layout` | `:id` (числовой ID цели) | Детальный просмотр цели, редактирование KR и добавление нового KR |
| `/completed` | `CompletedGoalsPage` | Вложен в `Layout` | — | Архив полностью выполненных целей (`прогресс = 100%`) |
| `*` | `NotFoundPage` | Вложен в `Layout` | — | Обработка неизвестных адресов (страница 404) |

**Защищённые маршруты:** в рамках текущей версии MVP авторизация и разграничение ролей пользователей не предусмотрены, поэтому все маршруты являются открытыми (публичными). При добавлении серверной авторизации на следующих этапах курсовой работы маршруты создания и редактирования будут обёрнуты в компонент `ProtectedRoute`.

## 5. Использование библиотеки общих компонентов основным приложением

1. **Подключение как локального пакета:** в `frontend/package.json` указана зависимость `"@my-app/ui-library": "file:../ui-library"`. При сборке `ui-library` (`npm run build`) формируются артефакты `dist/index.js`, `dist/index.d.ts` и `dist/index.css`.
2. **Подключение стилей:** в `frontend/src/App.tsx` однократно подключаются собранные стили библиотеки через `import '@my-app/ui-library/style.css'`.
3. **Использование компонентов и типов:** страницы и `Layout` импортируют готовые UI-компоненты (`OkrGoalCard`, `KeyResultList`, `Button`, `Card`), типы (`Goal`) и чистые утилиты (`calculateGoalProgress`, `calculateOverallProgress`, `getFilledSquaresCount`, `isValidTitle`, `isValidDate`, `isPositiveNumber`, `isValidId`) напрямую из `@my-app/ui-library`.
4. **Инверсия управления (Props & Callbacks):** компоненты в `ui-library` не привязаны к `localStorage` или роутеру — они получают текущие данные через `props` из хука `useGoals` и передают пользовательские действия обратно через колбэки (`onProgressChange`, `onToggleUrgent`, `onClick`), что позволяет в будущем подключить REST API без изменения кода `ui-library`.
