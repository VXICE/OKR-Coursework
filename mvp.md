# Функциональные требования к MVP: Система отслеживания целей OKR

## 1. Use Cases (Сценарии использования)

### Use Case 1: Создание новой цели OKR и добавление ключевых результатов

- **Актор:** Пользователь (владелец личных или учебных целей).
- **Предусловия:** Пользователь открыл веб-приложение в браузере на главной странице (`/`).
- **Основной сценарий:**
  1. Пользователь нажимает пункт навигации **«Создать цель»** (или кнопку **«Создать цель»** / **«Новая цель»**) и переходит на страницу `/create`.
  2. Пользователь заполняет поле **«Название цели»** (например, *«Выучить английский»*) и поле **«Срок выполнения (ДД.ММ.ГГГГ)»** (например, *«31.12.2026»*).
  3. Пользователь нажимает кнопку **«Создать цель»**.
  4. Система валидирует введённые данные, сохраняет новую цель с начальным статусом **«Не начато»** (`0%`) в локальное хранилище и автоматически перенаправляет пользователя на детальную страницу цели `/goals/:id`.
  5. На странице `/goals/:id` пользователь заполняет форму **«Привязать ключевой результат»**: вводит описание KR (например, *«Изучить Past Simple»*) и целевое значение больше `0` (например, `5`), после чего нажимает **«Добавить ключевой результат»**.
  6. Система добавляет ключевой результат к цели, отображает его в списке `KeyResultList` и рассчитывает его максимальный вклад в общий прогресс цели.
- **Результат:** Создана новая цель OKR с привязанными ключевыми результатами, данные сохранены в `localStorage` и не пропадают при перезагрузке страницы.
- **Альтернативные сценарии:**
  - *А1 (некорректное название):* Если название цели или KR пустое, длиннее 100 символов или начинается с `/`, система не сохраняет запись и выводит сообщение об ошибке под формой.
  - *А2 (некорректная дата):* Если дата указана не в формате `ДД.ММ.ГГГГ`, не существует в календаре или относится к прошлому, система отклоняет ввод и выводит подсказку по формату.
  - *А3 (некорректное целевое значение KR):* Если введено число `<= 0` или нечисловое значение, система выводит ошибку валидации.
  - *А4 (отмена создания):* Пользователь нажимает кнопку **«Отмена»** на странице `/create` и возвращается на главную страницу `/` без создания цели.

### Use Case 2: Обновление прогресса ключевых результатов и завершение цели

- **Актор:** Пользователь.
- **Предусловия:** В системе создана хотя бы одна активная цель с одним или несколькими ключевыми результатами; пользователь находится на главной странице (`/`) или на детальной странице цели (`/goals/:id`).
- **Основной сценарий:**
  1. Пользователь изменяет текущее значение выполнения одного из ключевых результатов с помощью ползунка (`range`) или числового поля (`number`).
  2. Компонент `KeyResultList` вызывает колбэк `onProgressChange`, обновляя значение `current` в состоянии приложения и `localStorage`.
  3. Система мгновенно пересчитывает процент выполнения KR, его фактический вклад в цель, итоговый прогресс-бар цели (`OkrGoalCard`), статус цели (например, с **«Не начато»** на **«В работе»**) и общий прогресс по всем целям в шапке.
  4. При необходимости пользователь нажимает **«Сделать срочным»**, переводя цель в статус **«Срочное»**.
  5. Когда все ключевые результаты цели достигают своего целевого значения (`current >= target`), прогресс цели становится равен `100%`, статус автоматически меняется на **«Выполнено»**, а цель перемещается в раздел **«Выполненные»** (`/completed`).
- **Результат:** Прогресс цели и общая статистика актуальны в реальном времени; завершённые цели и ключевые результаты отделены от активных.
- **Альтернативные сценарии:**
  - *А1 (частичное выполнение при больших числах):* Если `current < target` (например, `999` из `1000`), система ограничивает отображаемый прогресс значением `99%`, не помечая цель выполненной до фактического достижения целевого значения.
  - *А2 (несуществующий ID цели):* При прямом переходе по адресу `/goals/999` система отображает экран **«Цель не найдена»** с кнопкой возврата на `/`.

## 2. Границы MVP

### Входит в первую версию (MVP)
- Разделение проекта на библиотеку общих UI-компонентов (`ui-library`) и клиентское веб-приложение (`frontend`).
- Многостраничная навигация (`react-router-dom`): активные цели (`/`), создание цели (`/create`), детальная страница цели с параметром (`/goals/:id`), выполненные цели (`/completed`) и страница 404 (`*`).
- Создание целей OKR и привязка ключевых результатов с полной клиентской валидацией.
- Расчёт прогресса KR, вклада каждого KR в цель, итогового прогресса цели (сегментированный прогресс-бар из 10 квадратов + точный процент) и общего прогресса по всем целям.
- Управление статусами цели (`Не начато`, `В работе`, `Срочное`, `Выполнено`) и автоматическая сортировка выполненных элементов.
- Автоматическое сохранение данных в браузере (`localStorage`).
- Юнит- и интеграционное тестирование (Jest + React Testing Library) и контроль качества кода (TypeScript + ESLint).

### Остаётся за пределами MVP (будущие итерации курсовой работы)
- Серверная часть (REST API) и постоянное хранение данных в базе данных вместо `localStorage`.
- Регистрация, авторизация пользователей и защищённые маршруты (`ProtectedRoute`).
- Совместная работа нескольких пользователей над общими командными целями.
- Интеграция и синхронизация данных с Telegram-ботом в реальном времени.
- Удаление, архивирование и редактирование названий/дедлайнов уже созданных целей и KR, а также настраиваемые веса (приоритеты) для отдельных KR.
